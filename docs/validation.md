# 0.2.0 検証記録

2026-10-30、LinuxクラウドのChromiumとElectronで実施。

## 元Excelの再調査

入力1～3の欄構成、カレンダーとカレンダー2の見出し・行列、備考BE～BSの15列、関連VBAの転記・初期化・保存/呼出・並べ替え・ランク検索・印刷/PDFを静的に確認。元の印刷はB4横、1ページへの縮小設定でした。マクロは実行していません。

## 自動チェック

- ドメインロジック13テスト（既存6件＋シート機能7件）：年度境界・閏日・日程生成・重複・英検条件・復元形式・シート間の全項目往復・同日複数欄・年内/自由日付・欄超過・下書きの独立性・日付不正・順位/ランク/任意順序・分割備考15列と見出しの保存復元・旧版データの移行・ランク候補。
- Chromium画面テスト3件：既存機能の回帰、新しい入力1～3と両カレンダーの一連操作、ランク・並べ替え・表示設定・キャンセル保護と空行からの追加。
- Electron実プロセス：旧版JSONを読み込んで再起動、下書きからカレンダーへ反映、15列目と備考3の実ファイル保存、再起動後の復元、JSONバックアップ出力/取込、両カレンダーのPDF生成、路線図UI・カタログ用データの削除を確認。
- 全JavaScriptの構文チェック、git diffの空白チェック。

## PDF検証

両カレンダーのPDFはB4横（364×257mm）、テスト用2件の予定では1ページ。画像化して表・日程・備考を確認。PDFを pdftotext -raw で抽出し、大学名・分割備考15列目・備考1が含まれ、備考3が含まれないことを確認。UIテストでもPDF出力用HTMLに備考3を含めないことを確認しています。表形式の -layout 抽出は列と改行の順序が混在するため、値の照合には -raw を使用。

## 保存・互換性

保存スキーマはversion 1を維持し、旧版にない下書き・表示設定・生徒備考は追加フィールドとして扱います。既存予定を切り捨てず、入力欄を超える分は入力3の追加欄に保持します。生徒切替時のデータ混在、削除/反映のキャンセル、保存履歴からの復元を確認しています。

## 配布と検証の区別

GitHub ActionsにはWindows上での依存関係インストール・ドメインテスト・構文チェック・Electron実プロセステスト・Windows ZIPのビルド・成果物保存を設定しました。最新の実行結果はActionsで確認してください。Windowsの物理プリンターへの出力は検証対象外です。長大なデータ・長文での1ページ保証、Excelのセル座標/外観そのものの一致、元Excelの保存庫からの生徒データ移行は対象外です。

大学の公式募集要項との照合は行っていません。テストは専用の一時保存先を使い、元Excelの生徒名や実ユーザーの個人情報を使いません。

# Karenda — 受験校カレンダー・ツクール

Windows 10/11（64 bit）向けのデスクトップアプリ。2027年度入試 Excel の「入力1～3」「カレンダー」「カレンダー2」の操作を実装しています。Excel やインターネット接続なしで利用できます。バージョン0.2.0では路線図を削除しました。

## Windows版のダウンロード

GitHub の [Actions](https://github.com/stepminoura-svg/karenda/actions/workflows/windows-build.yml) で、最新の成功した実行を開きます。GitHub にログインし、下部の **Artifacts → Karenda-Windows-x64** をクリックしてください。成果物は30日間保存されます。

ダウンロードした ZIP を展開し、中の `Karenda-0.2.0-Windows-x64.zip` も展開して `Karenda.exe` を起動します。ZIP 内から直接起動せず、全ファイルを展開してください。署名なしの開発版です。

## 入力1～3

生徒は画面右上で選択し、「生徒・保存設定」で登録・編集します。各生徒の入力下書きとカレンダーは独立しています。

- 入力1：1/13～3/25の各日に、リスト選択2欄と手入力1欄。
- 入力2：同期間にリスト選択3欄。上段には年内など任意日付のリスト選択3欄。
- 入力3：同期間に手入力3欄。上段には試験日も自由に入力できる3欄。
- リストは試験日に応じて絞り込み、大学・学部・学科・方式から選べます。選択すると出願・発表・手続締切を自動入力します。手入力欄の「詳細」で出願日、ランク、順位、追加項目、備考も編集できます。
- **入力内容は下書き**として自動保存します。「カレンダーに反映」で反映先を選ぶと、現在のカレンダーが下書きの内容に置き換わります。反映前の状態は履歴に保存します。
- 「入力1～3を白紙」は選択中の生徒の下書きだけを消去し、カレンダーは変更しません。事前に下書きも履歴へ保存します。

元Excelに残っていた非閏年の2/29は表示しません。指定欄に収まらない既存予定は、入力3下部の追加欄として保持します。30件を超える既存データも切り捨てません。

## カレンダーとカレンダー2

**カレンダー**は、学校を行、日付を列にした横長の表です。日付のマスをクリックし、試験日・発表日・手続締切日を設定できます。同日に複数の印を設定できます。左側の情報も直接編集できます。空行の大学名欄から直接追加することもできます。期間は指定でき、「全日程を表示」で年内日程も表示します。

**カレンダー2**は、志望順位・ランク・大学・学部・学科・方式・4種の日付・追加3項目・備考を直接編集する一覧表です。備考は結合表示と15列の分割表示を切り替えられ、分割した見出しも生徒ごとに変更できます。

両カレンダーは同じ受験情報を表示します。Excelのような相互転記による情報欠落がなく、切り替えるだけで編集内容を引き継ぎます。次の操作は両画面から実行できます。

- 受験校をリスト・手入力から追加、詳細編集、削除。
- 試験日・順位・ランク・各期限で昇順／降順に並べ替え。行番号を指定した任意の順序にも対応。
- 「空欄のランクを調べる」で対象学部・学科を選んで反映。入力済みのランクは変更しません。
- 表示列や見出しの変更。カレンダー2は全列表示です。
- 計画の保存、保存履歴からの呼び出し、カレンダーから入力1～3への転記。ランク・順位・備考15列・見出しも保持します。
- B4横を標準に、A4／A3横の印刷・PDF保存。空の行・日付余白の省略を選べます。備考1・2は表の下に印刷し、備考3は印刷しません。

大学・入試検索、英検条件検索、キャンパス・最寄り駅検索、月間カレンダーは引き続き利用できます。路線図画面・駅ハイライト・地図画像は削除しました。

## 保存と旧版からの移行

保存先は通常 `%APPDATA%/karenda/students.json`。直前の保存は `students.json.bak` に保管します。0.1.0 の保存ファイル・JSONバックアップも読み込めます。実行ファイルの新しいフォルダーを展開して起動すれば、同じWindowsユーザーの保存データを使います。更新前に「生徒・保存設定」からバックアップを保存してください。

予定に加え、入力下書き・備考・見出し・表示設定・履歴を保存します。端末間の同期はありません。元Excelの生徒名・入力済みサンプルは収録していません。

## 開発

Node.js 24 と npm を使用します。

```sh
npm ci
npm start
npm test
npm run check
npm run test:ui
npm run test:desktop
npm run dist:win
```

Linux クラウドではプロキシに対応するため、必要に応じて `NODE_USE_ENV_PROXY=1 npm ci` と `NODE_USE_ENV_PROXY=1 node node_modules/electron/install.js` を使います。TLS・チェックサム検証は無効化しません。

UIテストは `/usr/bin/chromium`、ElectronテストはLinuxでheadless Ozoneを使用します。テストは専用の一時保存先を使い、実際の生徒データを変更しません。必要なら `playwright.config.cjs` の実行パスを調整してください。

学校データの再変換には Python と `openpyxl==3.1.5` が必要です。

```sh
python3 scripts/import_excel.py 入力ファイル.xlsm
```

VBAを実行せず、保存済みの計算結果を読み取ります。シートや列構成が変更された場合はスクリプトの更新が必要です。アプリ内のExcelインポート機能ではありません。

[元Excelとの対応表](docs/excel-parity.md)と[検証記録](docs/validation.md)を参照してください。日程・出願条件は元資料の転記で、大学の公式募集要項との照合は行っていません。
